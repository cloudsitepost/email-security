How Multiple DKIM Selectors

    Work For Different Email Services

    Businesses often rely on different email services for marketing, transactional messages, customer support, and internal communication. Each service may need its own DomainKeys Identified Mail (DKIM) setup to authenticate outgoing email. Multiple DKIM selectors make this possible: they let an organization publish and manage separate public keys for different providers under one domain. Each selector identifies the public key used to verify an email’s digital signature. Understanding how selectors work can help businesses manage email authentication, protect domain reputation, and support email deliverability.


    What Are DKIM Selectors?


    A DKIM selector is a unique identifier in an email’s DKIM signature. It points the receiving mail server to the public key it needs to verify the signature. The sending email service signs the message with a private key, while the matching public key is published in the domain’s DNS records. The receiving server uses the selector to find that key and validate the signature.

    For example, a domain might use the following DKIM DNS records:

    • google._domainkey.example.com

    • mailchimp._domainkey.example.com

    • salesforce._domainkey.example.com

    Each selector points to a different public key. This allows multiple email services to authenticate messages using the same organizational domain without relying on a single DKIM key.


    Why Do Businesses Need Multiple DKIM Selectors?


    Organizations often use multiple email providers to meet different communication needs—for example, Google Workspace for employee email, Mailchimp for marketing campaigns, and Salesforce for customer notifications.

    Using multiple DKIM selectors provides several advantages.




    1. Separate Authentication For Different Email Services

    Each email provider can use its own DKIM selector and private key, keeping authentication settings separate and making it easier to see which service signed a message. For example, Google Workspace might use the selector `google`, while a marketing platform uses `marketing`. Both can authenticate email sent from `example.com`.


    2. Easier DKIM Key Rotation

    Regularly updating DKIM keys helps maintain email security. Using multiple selectors can simplify rotation: administrators can publish a new selector, such as selector2, while selector1 remains in use. After updating the email service, they can verify that the new key works before retiring the old selector.


    3. Reduced Dependency On A Single Configuration

    When each service uses its own selector, updating one provider’s DKIM configuration doesn’t necessarily affect the others. This separation helps administrators troubleshoot authentication failures without disrupting every email service connected to the domain.


    How Multiple DKIM Selectors Work Together


    Multiple DKIM selectors work through DNS records and email headers. Although different services use separate selectors, they can all authenticate messages for the same domain.

    The process generally follows these steps:

    • Generate DKIM keys: Each email service either generates a public-private key pair or provides the DNS configuration you need.

    • Create DNS records: The administrator publishes the corresponding public key at the selector-specific _domainkey hostname.

    • Configure email services: Each provider signs outgoing messages with its assigned selector.

    Common DKIM Selector Configurations For Different Email Services


    Different email services can use separate DKIM selectors based on their authentication requirements. Administrators should follow the DNS configuration provided by each platform rather than assuming that all providers use the same selector format.

    Here are some common examples:


    1. Google Workspace

    Google Workspace lets organizations configure DKIM authentication for outgoing business email. An administrator generates a DKIM key in the Google Admin console, then adds the provided TXT record to the domain’s DNS settings. For example, the selector “google” creates the hostname google._domainkey.example.com. After the DNS changes are available, the administrator activates DKIM signing in Google Workspace, and outgoing emails include a DKIM signature associated with that selector.


    2. Mailchimp

    Email platforms such as Mailchimp use DKIM to help authenticate messages sent through their systems. To authorize a platform to sign email for an organization’s domain, administrators generally add the provider’s specified DNS records. For example, an illustrative selector named “marketing” could use the record name:

    marketing._domainkey.example.com

    Use the exact selector and record values provided by the email platform, as configurations vary.


    3. Salesforce

    Salesforce supports DKIM signing for emails sent through its platform. Administrators configure the required DKIM keys and publish the matching public key record in DNS. For example, a selector named “salesforce” could create `salesforce._domainkey.example.com`, allowing receiving mail servers to retrieve the public key to validate messages sent through Salesforce.
