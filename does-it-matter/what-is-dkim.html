What Is DKIM Canonicalization And Why Does
It Matter?


Email authentication plays an essential role in protecting businesses from phishing, spoofing, and unauthorized email activity. One of the most important technologies supporting email security is DomainKeys Identified Mail (DKIM). It allows receiving mail servers to verify that an email was authorized by the sending domain and that its signed content has not been improperly modified during transmission. However, DKIM relies on an important process called canonicalization, which helps ensure that minor formatting changes do not cause legitimate emails to fail authentication.

Understanding DKIM canonicalization is important for organizations that want reliable email delivery, stronger domain protection, and fewer authentication problems.


What Is DKIM Canonicalization?


DKIM canonicalization is the process of standardizing specific parts of an email before generating or verifying its digital signature. Email messages can undergo minor formatting changes as they travel between mail servers, gateways, and other email systems.

For example, a mail server might modify whitespace, adjust header formatting, or introduce additional line breaks. Without canonicalization, even small changes could cause a DKIM signature verification failure.

Canonicalization establishes consistent rules for interpreting email headers and message bodies. Both the sending and receiving systems use these rules to determine whether the signature remains valid.


Why Is Canonicalization Necessary?

Email messages pass through multiple systems before reaching their recipients. Some systems automatically modify formatting without changing the actual meaning of the message.

DKIM canonicalization helps manage these differences by defining which formatting changes should be ignored and which modifications should affect signature verification.





It helps organizations:

  • Reduce unnecessary DKIM authentication failures.

  • Maintain reliable email delivery.

  • Protect message integrity.

  • Improve compatibility between email platforms.

  • Support consistent email authentication.

1. Simple Canonicalization

Simple canonicalization applies strict formatting rules. It preserves most of the original email structure and allows very few modifications.

For email headers, the method generally requires the signed header content to remain unchanged. For message bodies, it removes certain trailing empty lines but otherwise preserves formatting.

This approach provides stricter integrity checking but can be sensitive to minor changes introduced by email systems.

Organizations using simple canonicalization should ensure that their email infrastructure does not unnecessarily modify signed messages.


2. Relaxed Canonicalization

Relaxed canonicalization allows certain harmless formatting changes while maintaining the integrity of the signed message.

For headers, it normalizes whitespace and header field formatting. For message bodies, it reduces unnecessary whitespace and removes trailing empty lines.

This makes relaxed canonicalization more flexible when emails pass through different mail servers and security gateways.

Many organizations prefer relaxed canonicalization because it reduces authentication problems caused by insignificant formatting differences.


How Does DKIM Canonicalization Work?


DKIM canonicalization works as part of the email signing and verification process.


Step 1: The Sending Server Prepares the Email

The sending mail server prepares the message and identifies the headers and body that will be included in the DKIM signature.


Step 2: Canonicalization Standardizes the Message

The server applies the selected canonicalization method to the relevant email components. This ensures that the message follows the required formatting rules before cryptographic processing.





Step 3: The DKIM Signature Is Generated

The sending server creates a cryptographic signature using its private key. The signature is added to the email's DKIM-Signature header.


Step 4: The Receiving Server Verifies the Signature

The receiving server retrieves the sender's public key from DNS and applies the specified canonicalization method. It then checks whether the signature matches the signed content.

If verification succeeds, the message passes DKIM authentication. If significant modifications have occurred, verification may fail.


Best Practices for Managing DKIM Canonicalization


Businesses should follow several practices to maintain reliable DKIM authentication:

  • Choose the appropriate method:Consider relaxed canonicalization when emails pass through multiple systems that may modify formatting.

  • Monitor authentication results: Regularly review DKIM failures and investigate unexpected verification problems.

  • Check DNS configuration: Ensure DKIM public keys and selectors are published correctly.

  • Coordinate email systems: Review gateways, forwarding services, and third-party email platforms for message modifications.

  • Use email authentication tools: Platforms such as MXToolbox, EasyDMARC, PowerDMARC, and AutoSPF can help organizations monitor authentication configurations and identify related issues.
